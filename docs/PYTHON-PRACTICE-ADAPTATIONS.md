# Daily coding practice: inspection and adaptations

Reviewed the public repository [`shaikhtaha258-maker/daily-coding-practice`](https://github.com/shaikhtaha258-maker/daily-coding-practice), read its README and inspected its tracked Python practice files from chapters 1 through 10. Its README describes it only as “coding practice.” The repository contains small string, collection, conditional, loop, function, file, and object-oriented exercises, with many chapter problem files that do not include prompts or explanations. It has no declared licence file. ZeroToCode should credit these as topic inspiration and independently write its own questions, explanations, examples, and solutions.

The useful editorial pattern is to turn one idea into a concrete task, make the learner predict a result, use a small value they can check by hand, then vary a meaningful case. The ideas below preserve that pattern while adding the missing prerequisites, edge cases, explained solutions, and verification expected in ZeroToCode.

| Source pattern | Useful course connection | Teaching and correctness requirements |
|---|---|---|
| [Chapter 2 string practice](https://github.com/shaikhtaha258-maker/daily-coding-practice/tree/ec6a2b2afc09e704ab2399a74f0299c8844ea1e2/chapter2): personalise a letter, find repeated spaces, replace them, and inspect newline/tab escapes | String methods, formatting, escaping, and customer messages | Explain that `find` returns `-1` when a substring is absent, `replace` returns a new string, and whitespace changes visible output. Never carry accidental source spacing or spelling errors into a new exercise. |
| [Chapters 3–4 collection practice](https://github.com/shaikhtaha258-maker/daily-coding-practice/tree/ec6a2b2afc09e704ab2399a74f0299c8844ea1e2/chapter3) and [dictionary/set practice](https://github.com/shaikhtaha258-maker/daily-coding-practice/tree/ec6a2b2afc09e704ab2399a74f0299c8844ea1e2/chapter4) | List building, tuple counting, lookup dictionaries, and unique values | State whether order matters, explain what duplicate keys or values do, and handle missing dictionary keys deliberately. Set display order is not a dependable sorted order; tests should check membership or sort compatible values. `10` and `10.0` compare equal and occupy one set entry; `18` and `"18"` remain distinct. |
| [Chapter 5 decision practice](https://github.com/shaikhtaha258-maker/daily-coding-practice/tree/ec6a2b2afc09e704ab2399a74f0299c8844ea1e2/chapter5): eligibility thresholds, keyword checks, membership, and case normalisation | If/elif decisions, comparisons, boolean combinations, and string membership | Define inclusive/exclusive boundaries, ties, invalid input, and case sensitivity before writing branches. The source’s grade ranges overlap at values such as 90 and 80, and its strict comparisons omit ties in its largest-of-four task. |
| [Chapter 6 loop practice](https://github.com/shaikhtaha258-maker/daily-coding-practice/tree/ec6a2b2afc09e704ab2399a74f0299c8844ea1e2/chapter6): multiplication tables, running totals, factorials, and printed patterns | `while`, `for`, `range`, accumulators, and loop control | Trace the state across iterations and test lower bounds such as zero and one. In the source prime example, the `else` is attached to the divisibility check inside the loop, so it can print “prime” for a composite number before finding a later divisor. Teach `for ... else` only in its actual, less common meaning. |
| [Chapter 7 function practice](https://github.com/shaikhtaha258-maker/daily-coding-practice/tree/ec6a2b2afc09e704ab2399a74f0299c8844ea1e2/chapter7) | Functions that return conversions, reusable calculations, print formatting, and recursion | Distinguish returned data from printed text. Test named boundary cases and explain a recursive base case before tracing a recursive call. |
| [Chapter 8 file exercises](https://github.com/shaikhtaha258-maker/daily-coding-practice/tree/ec6a2b2afc09e704ab2399a74f0299c8844ea1e2/chapter8) | Read, search, write, append, and replace file contents | Teach `with open`, encodings, missing files, relative paths, and preservation of original data. Use disposable fixture files; write to a new output file before attempting a replacement. Handle empty score files and constrain file creation to a dedicated temporary/project folder. |

The original examples are small starting points rather than vetted reference answers. Preserve a useful challenge, not an error: learners should get deterministic expected results, honest feedback, and an explained solution that addresses the boundary cases their own code might miss.
